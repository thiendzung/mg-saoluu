# MG Sao Lưu 1.3.0-rc2 — signed Local → fresh Production migration candidate

**Pre-release. Production Restore/Migration remains hard-blocked in every RC.**

This RC supersedes v1.3.0-rc1 for testing. It keeps the signed Local → fresh Production design, canonical WordPress host protection, matching DB-prefix requirement, fresh-target/HPOS guards, single-use Ed25519 approval, independent pre-restore checkpoint, domain rewrite with GUID preservation and staging-only QA gate.

## RC2 hardening
- The running MG Sao Luu plugin is never copied from the Local archive during migration.
- Those skipped plugin files are also excluded from the rollback-new inventory, so a later rollback cannot remove a plugin file that migration never created.
- Regression coverage explicitly checks that a signed migration enables source → target domain replacement on production logic, while an ordinary production restore cannot rewrite domains.
- Contract suite increases to 106 tests; migration security and staging QA suites remain separate.

## Still intentionally blocked / unsupported
- Any RC writing to a real production hostname.
- Overwriting an existing production site with real users, comments, orders/HPOS data or content beyond a fresh install.
- Different DB prefixes.
- wp-config.php, .htaccess, DNS/TLS, DB credentials, API keys, SMTP/payment/webhook/cron configuration.
- Guaranteed replacement inside unsafe/complex serialized object payloads.
- Claims of crash-atomic behavior under real physical ENOSPC or hard process kill unless separately tested.

Only an isolated Staging clone with explicit QA constants may exercise the mutation path. A future stable release requires exact-host pinning, HTTPS, disabled WP-Cron, explicit server opt-in, independent Recovery Kit, external-I/O isolation, runtime PASS and Founder approval.
