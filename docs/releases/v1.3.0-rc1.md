# MG Sao Lưu v1.3.0-rc1 — Local → Production migration candidate

**PRE-RELEASE / KHÔNG DÙNG TRÊN PRODUCTION ĐỂ RESTORE HOẶC MIGRATE.** Giao diện và backend bắt buộc chặn ghi production ở mọi bản `-rc`.

## Mục tiêu
- Backup, Verify, Restore và Rollback WordPress theo hướng an toàn và ít thao tác.
- Khi chuyển từ `abc.test` sang `example.com`: lấy URL nguồn từ manifest của backup, URL đích từ cấu hình WordPress đích; thay tham chiếu URL trong database nhưng không đổi `posts.guid`.
- Phân biệt **khôi phục cùng website thật** với **chuyển website từ Local sang production mới**. Không cho gói Local ghi đè một web thật đang có dữ liệu.

## Luồng dự kiến trong phiên bản stable sau nghiệm thu
1. Local: tạo **gói mã hóa riêng để chuyển site** (`local_copy`, `purpose=migration`), Verify và lưu Recovery Key ngoài webroot.
2. Cài WordPress đích trắng với DB riêng, **prefix giống nguồn**, HTTPS đúng canonical URL, cài MG Sao Lưu. Đảm bảo không có đơn hàng, khách, nội dung cần giữ.
3. Ghép nối public key của Local vào MG Sao Lưu trên host; private key **chỉ có ở Local**.
4. Chặn outbound SMTP, WooCommerce checkout/payments, webhooks/Action Scheduler, đặt `DISABLE_WP_CRON=true`; có checkpoint ngoài host và cách khôi phục độc lập trước.
5. Host: tải **một lần** gói mã hóa vào kho riêng, giải mã/kiểm nội dung và xem nguồn → đích **không ghi database**.
6. Local: chọn đúng gói và HTTPS domain, tạo mã ký Ed25519 gắn với **SHA-256, URL nguồn, URL đích, nonce, hạn 10 phút**.
7. Host: chọn gói đã kiểm, nhập mã ký, Recovery Key, admin password và câu xác nhận. Stable-only code + **cấu hình opt-in trên server** kiểm tra chữ ký, nonce chưa dùng, DB đích trắng, prefix, dung lượng và tạo checkpoint trước khi nhập.
8. Sau nhập: cập nhật URL → đích, giữ GUID, giữ phiên bản MG Sao Lưu đang chạy trên host, kiểm media, WP admin, CPT, Product/HPOS; chỉ mở lưu lượng/cron/email/payment khi hoàn thành nghiệm thu.

## Giới hạn / STOP
- Không hỗ trợ **ghi đè một website production đang có khách, đơn hàng, nội dung thật**; trường hợp đó cần migration nội dung theo kiểu merge và cutover được thiết kế riêng.
- Không tự chuyển `wp-config.php`, `.htaccess`, TLS, DNS, DB user/host, Secrets, API keys, cron, file ownership hay cấu hình PHP/server.
- Gói mã hóa vẫn có thể chứa dữ liệu người dùng và mật khẩu hash của database nguồn; giữ kín, không đăng log/tài liệu.
- Phần serialized object/phức tạp có thể giữ lại URL nguồn; cần soát ở clone trước cutover.
- Prefix khác nhau sẽ bị chặn; không tự động đổi prefix.
- Source/destination database đang có thể khác MySQL/MariaDB; phải test trên host đích. Mid-write disk-full, hard-kill, atomicity toàn site chưa được chứng minh.
- `MG_SAOLUU_ENABLE_PRODUCTION_MIGRATION`, `MG_SAOLUU_EXPECTED_TARGET_HOST` (khóa đúng hostname trong wp-config) và `DISABLE_WP_CRON` là điều kiện bổ sung của stable, **không mở khóa bất kỳ RC nào**. Không bật trên `motgu.com` chỉ vì thấy tùy chọn có trong mã.
- Agent Local có thể diễn tập trên hostname clone `staging.example.com` (chỉ DNS/hosts test, không phải website thật) khi đồng thời khai báo `WP_ENVIRONMENT_TYPE=staging`, `MG_SAOLUU_MIGRATION_QA_MODE=true`, `DISABLE_WP_CRON=true`, HTTPS và cách ly network. Cổng QA không hoạt động trên `motgu.com` hay hostname không bắt đầu bằng stage/staging/test/sandbox.
- Chỉ khi Agent Local có evidence PASS trên clone giống môi trường hosting, kiểm tra rollback và Founder cho phép mới xem xét phát hành stable.

## Acceptance
- GitHub PHP 8.3 lint, source + extracted integrity, ZIP CRC, contracts và Ed25519 negative gates.
- Clone SOURCE khác clone TARGET, mỗi clone DB/user/webroot, ứng dụng bên ngoài bị chặn.
- Chạy Local backup `purpose=migration`; verify, ký gói; stage trên site đích cô lập, so SHA và manifest.
- Positive: URL `abc.test` → hostname đích + CPT/Woo/Media + GUID bất biến + asset HTTP200.
- Negative: giả Host header, gói không mã hóa/sai purpose, prefix khác, hết hạn, token sai domain/SHA, token dùng lại, signer chưa ghép nối, target có users/orders/HPOS, RC production gate.
- Fault injection chỉ trên clone: SQL partial, journal gián đoạn, rollback file mới >0 và kiểm DB/checkpoint.
- Chứng cứ riêng tư; không dùng dữ liệu thật hoặc cung cấp Recovery Key cho GitHub.

**Không merge, không deploy, không tự bật production restore từ RC.**
